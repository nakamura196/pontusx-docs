# Ocean CLI でデータセットを利用する（Ocean Enterprise v2）

本ガイドは [ocean.js でデータセットを利用する](/ja/docs/oe-automation/consume/ocean-js) と
**同じ結果**（DDO v5 のデータセットの注文とダウンロード）を得るための手順ですが、コードを書く代わりに
既製の [Ocean CLI](https://github.com/oceanprotocol/ocean-cli) を使います。対象は `did:ope` の DID で
識別される Ocean Enterprise のアセットです。

:::info
とにかくファイルが欲しい場合や、ライブラリを自分のアプリに組み込む前に DID を確認したい場合は、この
**ノーコードの方法** を使ってください。処理の背景にある考え方については
[利用の概要](/ja/docs/oe-automation/consume/overview) を参照してください。
:::

## 前提条件（必須）

- **Node.js**（ocean.js のサンプルリポジトリに合わせ Node 24 を推奨）。
- **Git**。
- 資金のあるアカウント（`PRIVATE_KEY`）、**RPC** エンドポイント、**Ocean Node** の URL。
- 対象チェーンの **RPC** と **Ocean Node** へのネットワークアクセス。
  - **RPC** については、[公開 RPC](https://chainlist.org/chain/11155420) を使うか、deltaDAO に RPC の利用について問い合わせてください。
  - **Ocean Node** については、自前で運用するか、deltaDAO などのサービス提供者が提供するものを利用できます。
- 公開済み v5 データセットの **`did:ope`**。

:::info
`did:ope` は Pontus-X カタログで探せます。`RPC` と `NODE_URL` が、そのアセットが公開された
**同じネットワーク** を指していることを確認してください
（[Pontus-X ネットワーク](/ja/docs/pontus-x-networks/quick-start)）。
:::

## ステップ 1 — CLI をインストールする（必須）

```bash
git clone https://github.com/oceanprotocol/ocean-cli.git
cd ocean-cli
npm install
npm run build
```

## ステップ 2 — 環境を設定する（必須）

CLI はすべて環境変数で制御します。

```bash
# アカウント: PRIVATE_KEY か MNEMONIC のいずれかを使います
export PRIVATE_KEY="0x..."

# アセットが存在するチェーンの JSON-RPC エンドポイント
export RPC="https://your-rpc-endpoint"

# Ocean Node（メタデータキャッシュ + provider）
export NODE_URL="https://your-ocean-node"
```

:::warning
**開発専用** の秘密鍵を使い、安全に保管してください。鍵をコミットしたり共有したりしないでください。
:::

:::info
`MNEMONIC` は `PRIVATE_KEY` の **任意の** 代替手段です。どちらか一方を設定してください。
:::

### ステップ 2a — ウォレットファイルから `PRIVATE_KEY` を取り出す（任意）

[ウォレットファイルの設定](/ja/docs/getting-started/wallet-setup) を通じてオンボーディングした場合、
手元にあるのは生の秘密鍵ではなく **暗号化された JSON キーストア**（v3）です。次のような形をしています。

```json
{"address":"cb638bc3e4ea03072f6e0ebf43a8f514c63f0eea","id":"71fe0cd9-77cc-4539-a0d4-f5ee68a0754d","version":3,"Crypto":{ ... },"x-ethers":{ ... }}
```

CLI が期待する `0x…` 形式の秘密鍵を得るために、一度だけ復号します。`ethers` は CLI の依存関係に
含まれているため、`ocean-cli` フォルダから次の短いスクリプトを実行できます。

```js
// extract-key.mjs
import { readFileSync } from "node:fs";
import { Wallet } from "ethers";

const json = readFileSync(process.argv[2], "utf8");
const password = process.env.WALLET_PASSWORD;

const wallet = await Wallet.fromEncryptedJson(json, password);
console.log(wallet.privateKey); // 0x...
```

```bash
WALLET_PASSWORD="your-wallet-password" node extract-key.mjs ./wallet.json
```

出力された `0x…` の値を `PRIVATE_KEY` としてエクスポートします。

:::warning
ウォレットファイルの復号は信頼できるマシン上でのみ行ってください。ウォレットファイル、そのパスワード、
取り出した秘密鍵は決してコミットしないでください。
:::

### ステップ 2b — SSI ウォレット関連の変数（任意）

**クレデンシャルで保護された（SSI）v5 アセット** の場合は、CLI がポリシーサーバーへのプレゼンテーション
処理を完了できるよう、SSI ウォレット関連の変数も設定します
（[v2 の 2 ウォレット構成](/ja/docs/getting-started/wallet-setup) を参照）。

```bash
export SSI_WALLET_API="https://your-ssi-wallet/api"
export SSI_WALLET_ID="your-wallet-id"
export SSI_WALLET_DID="did:example:your-did"   # 任意。省略時は最初のウォレット DID が使われます
```

:::info
アセットがクレデンシャルで保護されて **いない** 場合、SSI 関連の変数は省略できます。
:::

## ステップ 3 — データセットをダウンロードする（必須）

位置引数の形式：

```bash
npm run cli download <did> [folder] [serviceId]
```

フラグの形式：

```bash
npm run cli download --did <did> --folder ./downloads --service <serviceId>
```

- `<did>` — **必須**。例：`did:ope:abc123...`
- `[folder]` — *任意*。出力先ディレクトリ（既定はカレントディレクトリ）。
- `[serviceId]` — *任意*。既定ではアセットの最初のダウンロードサービスが使われます。

例：

```bash
npm run cli download did:ope:1234abcd... ./downloads
```

成功すると、CLI は `File downloaded successfully: ./downloads/<filename>` と出力します。

## CLI が内部で行っていること

CLI は[ライブラリ版のガイド](/ja/docs/oe-automation/consume/ocean-js) とまったく同じ手順を実行します。

1. Ocean Node から DDO を解決する（`aquarius.waitForIndexer`）。
2. DDO のバージョンを判定し、`>= 5.0.0` の場合は SSI のプレゼンテーション処理を通じて
   **ポリシーサーバー用オブジェクト** を構築する（`getPolicyServerOBJ`）。
3. 対象サービスの datatoken を注文する（`orderAsset`）。
4. 署名付きのダウンロード URL を要求する（`ProviderInstance.getDownloadUrl`）。
5. ファイルを出力フォルダへ書き出す。

:::info
ライブラリ版のガイドとの違いは、CLI が SSI のクレデンシャル提示を **完全に実装している** 点です。
一方 ocean.js のサンプルには、処理を止めないスタブが同梱されており、必要に応じて拡張できます。
:::

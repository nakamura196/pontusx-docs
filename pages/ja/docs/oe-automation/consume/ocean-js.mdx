# ocean.js でデータセットを利用する（Ocean Enterprise v2）

本ガイドでは、[`ocean.js`](https://github.com/oceanprotocol/ocean.js) を用いて、自分の
Node.js／TypeScript アプリケーションから **DDO v5 のデータセットを注文してダウンロードする** 方法を
解説します。ポータルは使いません。対象は `did:ope` の DID で識別される Ocean Enterprise のアセットです。

:::info
こちらは **コードを書く方法** です。コードなしでファイルだけ欲しい場合は
[Ocean CLI のガイド](/ja/docs/oe-automation/consume/ocean-cli) を使ってください。どちらも同じ結果に至ります。
処理の背景にある考え方については [利用の概要](/ja/docs/oe-automation/consume/overview) を参照してください。
:::

:::info
本ガイドで使う完全に動作するサンプルコードは
[`deltaDAO/oe-automation-examples`](https://github.com/deltaDAO/oe-automation-examples) にあります。
以下のコード片はすべて、このリポジトリからそのまま引用しています。手順を最初から最後まで実行するには、
リポジトリをクローンしてください。
:::

## 前提条件（必須）

- **Node.js 24** — サンプルリポジトリが `.nvmrc` で固定しています。`nvm use` を実行してください。
- 次の資金があるアカウント（`PRIVATE_KEY`）：
  - ガス用のチェーンのネイティブトークン。
  - サービスが有償の場合は、そのアセットの決済トークンの十分な残高。
    - Pontus-X v2 は決済に EURAU（AllUnity）と EURC（Circle）に対応しています。テストネットワーク用トークンについてはお問い合わせください。
- 対象チェーンの **RPC** と **Ocean Node** へのネットワークアクセス。
  - **RPC** については、[公開 RPC](https://chainlist.org/chain/11155420) を使うか、deltaDAO に RPC の利用について問い合わせてください。
  - **Ocean Node** については、自前で運用するか、deltaDAO などのサービス提供者が提供するものを利用できます。
- 公開済み v5 データセットの **`did:ope`**。例：`did:ope:c4f73e09f932f50520d89d50245374a442fb6bca37e5659af1711703e3cc6f53`

:::info
`did:ope` は Pontus-X カタログで探せます。`RPC` と `NODE_URL` が、そのアセットが公開された
**同じネットワーク** を指していることを確認してください
（[Pontus-X ネットワーク](/ja/docs/pontus-x-networks/quick-start)）。
:::

テンプレートをコピーして値を埋めます。

### ステップ 2a — ウォレットファイルから `PRIVATE_KEY` を取り出す（任意）

[ウォレットファイルの設定](/ja/docs/getting-started/wallet-setup) を通じてオンボーディングした場合、
手元にあるのは生の秘密鍵ではなく **暗号化された JSON キーストア**（v3）です。次のような形をしています。

```json
{"address":"cb638bc3e4ea03072f6e0ebf43a8f514c63f0eea","id":"71fe0cd9-77cc-4539-a0d4-f5ee68a0754d","version":3,"Crypto":{ ... },"x-ethers":{ ... }}
```

本ガイドが前提とする `0x…` 形式の秘密鍵を得るために、一度だけ復号します。サンプルリポジトリには
`ethers` が同梱されているため、次の短いスクリプトを実行できます。

```js
// extract-key.mjs
import { readFileSync } from "node:fs";
import { Wallet } from "ethers";

const json = readFileSync(process.argv[2], "utf8");
const password = process.env.WALLET_PASSWORD;

const wallet = await Wallet.fromEncryptedJson(json, password);
console.log(wallet.privateKey); // 0x...
```

```bash
WALLET_PASSWORD="your-wallet-password" node extract-key.mjs ./wallet.json
```

出力された `0x…` の値を、`.env` の `PRIVATE_KEY` に貼り付けてください。

:::warning
ウォレットファイルの復号は信頼できるマシン上でのみ行ってください。ウォレットファイル、そのパスワード、
取り出した秘密鍵は決してコミットしないでください。
:::

### ステップ 2b — SSI ウォレット関連の変数（任意）

**クレデンシャルで保護された** アセットの場合にのみ必要です
（[v2 の 2 ウォレット構成](/ja/docs/getting-started/wallet-setup) を参照）。

```bash
# 任意 — クレデンシャルで保護された（SSI）アセットの場合のみ
SSI_WALLET_API=
SSI_WALLET_ID=
SSI_WALLET_DID=
```

:::info
アセットがクレデンシャルで保護されて **いない** 場合、これらは未設定のままで構いません。未設定の場合、
サンプルは警告を出したうえで処理を続けます。クレデンシャルの検査は Ocean Node 側で引き続き行われます。
:::

### 設定がどう結び付いているか

環境変数から実行時設定への橋渡しは `src/config.ts` にあります。

- `createSigner()` — `PRIVATE_KEY` と `RPC` から `ethers` の `Wallet` を作り、ネットワークから
  `chainId` を読み取ります。
- `createOceanConfig()` — ocean.js の `ConfigHelper` でチェーンの既定値を読み込み、オフチェーンの
  参照先をすべて単一の `NODE_URL` に向けます。
- `createAquarius()` — メタデータキャッシュのクライアント。これも Ocean Node が提供します。

## ステップ 3 — 実行する（必須）

```bash
npm run consume -- <did> [outputDir] [serviceId]
```

- `<did>` — **必須**。例：`did:ope:abc123...`
- `[outputDir]` — *任意*。ファイルの書き出し先（既定は `./downloads`）。
- `[serviceId]` — *任意*。既定ではアセットの最初のサービスが使われます。

### 1. アセットを解決する

```ts
const ddo = await aquarius.waitForIndexer(did)
if (!ddo) throw new Error(`Asset ${did} was not found on the Ocean Node.`)
```

`waitForIndexer` は、アセットがインデックスされるまで Ocean Node をポーリングし、DDO ドキュメントを
返します。

### 2. v5 であることを確認し、サービスを選ぶ

```ts
if (!isV5Asset(ddo)) {
  throw new Error('This guide targets DDO v5 assets only; the resolved asset is not v5.')
}

const { services } = DDOManager.getDDOClass(ddo).getDDOFields() as {
  services: Array<{ id: string }>
}
const serviceId = serviceIdArg ?? services[0].id
const serviceIndex = services.findIndex((s) => s.id === serviceId)
```

`DDOManager`（`@oceanprotocol/ddo-js` 由来）は生の DDO を適切なバージョンのクラスへ解析します。
`isV5Asset`（`src/policyServer.ts` 内）は DDO の `version` が `>= 5.0.0` であることを確認します。

### 3. ポリシーサーバーとその `sessionId` を取得する

```ts
const policyServer = await getPolicyServer(ddo, serviceId, signer, nodeUrl)
console.log(
  policyServer?.sessionId
    ? `Sending policyServer.sessionId to the node: ${policyServer.sessionId}`
    : 'No policyServer object; the node will enforce credentials itself.'
)
```

`getPolicyServer` は `policyServer` オブジェクトを返します。その中心となるフィールドが
**`sessionId`** です。このセッション ID は Ocean Node（`initializePSVerification`）が発行し、
`(consumerAddress, documentId, serviceId)` の組に紐づけられます。

:::warning
**Ocean Node にポリシーサーバーが設定されている（SSI 検証が有効な）場合、アクセス制御が設定された
アセットは `sessionId` なしではダウンロードに失敗します。** この場合、ノードの `download` アクションは、
ポリシーサーバーから取得した `sessionId` を持たないリクエストをすべて拒否します。しかも、SSI の
プレゼンテーションが必要かどうかを判断する **前** に拒否します。したがって `credentials` ブロックを持つ
アセットでは、セッション ID はここで必ず取得し、ステップ 5 で渡す必須の「チケット」になります。
:::

:::info
任意なのは SSI クレデンシャルの **提示（presentation）**（walt.id）の部分で、これはアセットに
`SSIpolicy` がある場合にのみ実行されます。`credentials` ブロックをまったく持たないアセットでは、
`getPolicyServer` は `undefined` を返し、セッション ID なしで処理が続きます。それ以外の点で
`getPolicyServer` は **処理を止めません**。SSI ウォレットの環境変数が未設定だったり、SSI の処理が
例外を投げたりした場合は、警告に格下げされます。
:::

最終的な判断は常に Ocean Node が行います。クレデンシャルが実際に必要な場合、次のステップで
ダウンロードが拒否されます。walt.id ／ポリシーサーバーのプレゼンテーションの完全な参照実装は
Ocean CLI（`getPolicyServerOBJ`）にあります。

### 4. datatoken を注文する

```ts
const datatoken = new Datatoken(signer, chainId, config)
const tx = await orderAsset(
  ddo, signer, config, datatoken, nodeUrl,
  undefined, undefined, undefined, undefined, undefined,
  serviceIndex
)
const orderTx = await tx.wait()
```

`orderAsset` は datatoken の価格設定（固定レート交換、ディスペンサー、あるいは保有済み）を調べ、
選択したサービスに対して有効な注文トランザクションを作るために必要な処理を行います。

### 5. ダウンロード URL を取得してファイルを保存する

```ts
const downloadResult = await ProviderInstance.getDownloadUrl(
  ddo.id, serviceId, 0, orderTx.hash, nodeUrl, signer, policyServer
)

const { data, filename } = await downloadFile(downloadResult)
fs.writeFileSync(path.join(outputDir, filename ?? 'file.out'), Buffer.from(data))
```

ステップ 3 で得た `policyServer` オブジェクトを **最後の引数** として渡すことで、その `sessionId` が
リクエストとともに送られます。クレデンシャルで保護されたアセットの場合、これを省略したり
`sessionId` を持たないオブジェクトを渡したりすると、ノードはダウンロードを拒否します。

`getDownloadUrl` は注文の所有を Ocean Node に対して証明し、ノードは署名付き URL（またはペイロード
そのもの）を返します。この署名付き URL は **1 回限り** 有効なので、ちょうど 1 回だけ取得して
ディスクへ書き出します。

## ソースコード全文

ここまでの内容は 3 つのファイルに収められており、[サンプルリポジトリ](https://github.com/deltaDAO/oe-automation-examples)

### `src/config.ts`

`.env` の内容を、ethers の署名者、ocean.js の `Config`、そして Aquarius のメタデータクライアントへ
変換します。

```ts
import 'dotenv/config'
import { JsonRpcProvider, Wallet, type Signer } from 'ethers'
import { Aquarius, ConfigHelper, type Config } from '@oceanprotocol/lib'

// 必須の環境変数が欠けていれば早期に例外を投げる。
export function requireEnv(name: string): string {
  const value = process.env[name]
  if (!value) throw new Error(`Missing required environment variable: ${name}`)
  return value
}

// PRIVATE_KEY と RPC から ethers の Wallet を作り、その chainId を読み取る。
export async function createSigner(): Promise<{ signer: Signer; chainId: number }> {
  const provider = new JsonRpcProvider(requireEnv('RPC'))
  const signer = new Wallet(requireEnv('PRIVATE_KEY'), provider)
  const { chainId } = await provider.getNetwork()
  return { signer, chainId: Number(chainId) }
}

// ocean.js のチェーン既定値を読み込み、オフチェーンの参照先をすべて NODE_URL に向ける。
export function createOceanConfig(chainId: number, nodeUrl: string): Config {
  const config = new ConfigHelper().getConfig(chainId)
  config.nodeUri = nodeUrl
  return config
}

// メタデータキャッシュのクライアント。これも Ocean Node が提供する。
export function createAquarius(nodeUrl: string): Aquarius {
  return new Aquarius(nodeUrl)
}
```

### `src/policyServer.ts`

v5 アセットを検出し、ポリシーサーバーの `sessionId`（および任意の walt.id クレデンシャル提示）を
解決します。意図的に **処理を止めない** 設計であり、最終的な判断は Ocean Node が行います。

```ts
import { type Signer } from 'ethers'
import { ProviderInstance } from '@oceanprotocol/lib'
import { DDOManager, type Asset } from '@oceanprotocol/ddo-js'

const V5_MIN_VERSION = '5.0.0'

// 「version >= minimum」を数値として比較する（文字列ソートの落とし穴を避ける）。
export function isVersionGte(version: string | undefined, minimum: string): boolean {
  if (!version) return false
  const parse = (v: string) => v.split('.').map((n) => parseInt(n, 10) || 0)
  const a = parse(version)
  const b = parse(minimum)
  for (let i = 0; i < Math.max(a.length, b.length); i++) {
    const x = a[i] ?? 0
    const y = b[i] ?? 0
    if (x !== y) return x > y
  }
  return true
}

// DDO が v5（Ocean Enterprise）のアセットなら true。
export function isV5Asset(ddo: Asset): boolean {
  const { version } = DDOManager.getDDOClass(ddo).getDDOFields() as { version?: string }
  return isVersionGte(version, V5_MIN_VERSION)
}

// Ocean Node がポリシーサーバーへ渡すオブジェクト。検証が成功したあとに
// 意味を持つのは `sessionId` だけ。
export interface PolicyServerInitiateActionData {
  sessionId: string
  successRedirectUri: string
  errorRedirectUri: string
  responseRedirectUri: string
  presentationDefinitionUri: string
}

interface SsiWalletSession { token: string }
interface SsiWalletDid { did: string }
interface SsiVerifiableCredential { id: string }

type InitiateMessage =
  | string
  | { sessionId?: string; redirectUri?: string }
  | undefined

// ポリシーサーバーは、リダイレクト／openid4vp の URI の中に
// `sessionId=<id>` か `id=<id>` の形でセッション ID を載せてくる。
function sessionIdFromUri(uri: string | undefined): string {
  if (typeof uri !== 'string') return ''
  const match = /[?&](?:sessionId|id)=([^&#]+)/.exec(uri)
  return match ? decodeURIComponent(match[1]) : ''
}

// ノードが返し得るどの形（オブジェクト／JSON／URL）からもセッション ID を取り出す。
function extractSessionId(message: InitiateMessage): string {
  if (!message) return ''
  if (typeof message === 'object') {
    return message.sessionId || sessionIdFromUri(message.redirectUri)
  }
  try {
    const parsed = JSON.parse(message)
    return (
      parsed?.sessionId ||
      parsed?.message?.sessionId ||
      sessionIdFromUri(parsed?.redirectUri) ||
      sessionIdFromUri(parsed?.message?.redirectUri) ||
      sessionIdFromUri(message)
    )
  } catch {
    return sessionIdFromUri(message)
  }
}

// openid4vp のリクエスト文字列を取り出す（実際に提示を行う場合のみ必要）。
function extractOpenid4vc(message: InitiateMessage): string | undefined {
  if (!message) return undefined
  if (typeof message === 'object') return message.redirectUri
  try {
    const parsed = JSON.parse(message)
    return parsed?.redirectUri ?? parsed?.message?.redirectUri ?? message
  } catch {
    return message
  }
}

// --- walt.id wallet-api 用のヘルパー（native fetch を使用。クレデンシャルはウォレットが保持）---

// オンチェーンの鍵で nonce に署名して SSI ウォレットにログインする。
async function connectToSSIWallet(signer: Signer, api: string): Promise<SsiWalletSession> {
  const nonceRes = await fetch(`${api}/wallet-api/auth/account/web3/nonce`)
  if (!nonceRes.ok) throw new Error(`SSI wallet nonce request failed: ${nonceRes.status}`)
  const nonce = await nonceRes.text()

  const signedRes = await fetch(`${api}/wallet-api/auth/account/web3/signed`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      challenge: nonce,
      signed: await signer.signMessage(nonce),
      publicKey: await signer.getAddress()
    })
  })
  if (!signedRes.ok) throw new Error(`SSI wallet login failed: ${signedRes.status}`)
  return signedRes.json() as Promise<SsiWalletSession>
}

async function getWalletDids(walletId: string, token: string, api: string): Promise<SsiWalletDid[]> {
  const res = await fetch(`${api}/wallet-api/wallet/${walletId}/dids`, {
    headers: { Authorization: `Bearer ${token}` }
  })
  if (!res.ok) throw new Error(`Fetching wallet DIDs failed: ${res.status}`)
  return res.json() as Promise<SsiWalletDid[]>
}

// 提示定義（presentation definition）を満たすクレデンシャルはどれか、ウォレットに問い合わせる。
async function matchCredentialsForPresentationDefinition(
  api: string,
  walletId: string,
  presentationDefinition: unknown,
  token: string
): Promise<SsiVerifiableCredential[]> {
  const res = await fetch(
    `${api}/wallet-api/wallet/${walletId}/exchange/matchCredentialsForPresentationDefinition`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${token}` },
      body: JSON.stringify(presentationDefinition)
    }
  )
  if (!res.ok) throw new Error(`Matching credentials failed: ${res.status}`)
  return res.json() as Promise<SsiVerifiableCredential[]>
}

async function resolvePresentationRequest(
  walletId: string,
  presentationRequest: string,
  token: string,
  api: string
): Promise<string> {
  const res = await fetch(
    `${api}/wallet-api/wallet/${walletId}/exchange/resolvePresentationRequest`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${token}` },
      body: JSON.stringify(presentationRequest)
    }
  )
  if (!res.ok) throw new Error(`Resolving presentation request failed: ${res.status}`)
  return res.text()
}

// 選んだクレデンシャルを検証可能プレゼンテーションとして提出する。
async function sendPresentationRequest(
  walletId: string,
  did: string,
  presentationRequest: string,
  selectedCredentials: string[],
  token: string,
  api: string
): Promise<{ redirectUri?: string; errorMessage?: string }> {
  const res = await fetch(
    `${api}/wallet-api/wallet/${walletId}/exchange/usePresentationRequest`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${token}` },
      body: JSON.stringify({ did, presentationRequest, selectedCredentials })
    }
  )
  if (!res.ok) throw new Error(`Submitting presentation failed: ${res.status}`)
  return res.json() as Promise<{ redirectUri?: string; errorMessage?: string }>
}

// セッションに対応する提示定義を取得する（`getPD` アクションはノードが中継する）。
async function getPresentationDefinition(sessionId: string, nodeUrl: string): Promise<unknown> {
  const response = await ProviderInstance.PolicyServerPassthrough(nodeUrl, {
    policyServerPassthrough: { action: 'getPD', sessionId }
  })
  const message = response?.message
  if (!message) throw new Error('Could not read presentation definition from policy server')
  return message
}

// --- クライアント側での DDO の検査（ポリシーサーバーの検査内容に対応）---

interface CredentialEntry { type?: string; values?: unknown[] }
interface CredentialsBlock { allow?: CredentialEntry[]; deny?: CredentialEntry[] }
interface CredentialSubject {
  credentials?: CredentialsBlock
  services?: Array<{ id: string; credentials?: CredentialsBlock }>
}

function getCredentialSubject(ddo: Asset): CredentialSubject | undefined {
  return (ddo as unknown as { credentialSubject?: CredentialSubject }).credentialSubject
}

// ノードがポリシーサーバーに問い合わせるのは、`credentials` ブロックが
// （アセットまたはサービスの階層に）存在する場合のみ。無ければセッション ID は不要。
function hasCredentialsBlock(ddo: Asset, serviceId: string): boolean {
  const subject = getCredentialSubject(ddo)
  if (subject?.credentials) return true
  const service = subject?.services?.find((s) => s.id === serviceId)
  return Boolean(service?.credentials)
}

// request_credentials を伴う `SSIpolicy` がある場合にのみ true。アドレスのみの
// 制限では、セッション ID は要るがウォレットからの提示は不要。
function requiresCredentialPresentation(ddo: Asset, serviceId: string): boolean {
  const subject = getCredentialSubject(ddo)
  if (!subject) return false
  const isSsi = (e: CredentialEntry) => e?.type === 'SSIpolicy'
  const assetPolicies = subject.credentials?.allow?.filter(isSsi) ?? []
  const service = subject.services?.find((s) => s.id === serviceId)
  const servicePolicies = service?.credentials?.allow?.filter(isSsi) ?? []
  for (const policy of [...assetPolicies, ...servicePolicies]) {
    if (!Array.isArray(policy.values)) continue
    for (const value of policy.values) {
      const requested = (value as { request_credentials?: unknown[] })?.request_credentials
      if (Array.isArray(requested) && requested.length > 0) return true
    }
  }
  return false
}

/**
 * ダウンロード時にノードが必要とするポリシーサーバー用オブジェクトを解決する。
 *   0. credentials ブロックが無い        -> ノードは PS に問い合わせない。undefined を返す。
 *   1. initializePSVerification         -> sessionId というチケットを発行させる。
 *   2. SSIpolicy が無い（例：アドレス制限）-> { sessionId } を返す。
 *   3. SSIpolicy がある                  -> walt.id の提示処理を実行し、
 *      その後 { sessionId } を返す。
 * 処理は止めない：失敗はすべて警告に格下げされる。
 */
export async function getPolicyServer(
  ddo: Asset,
  serviceId: string,
  signer: Signer,
  nodeUrl: string
): Promise<PolicyServerInitiateActionData | undefined> {
  // 0. 制限すべきものが無い。
  if (!hasCredentialsBlock(ddo, serviceId)) return undefined

  const consumerAddress = await signer.getAddress()
  const policyServer: PolicyServerInitiateActionData = {
    sessionId: '',
    successRedirectUri: '',
    errorRedirectUri: '',
    responseRedirectUri: '',
    presentationDefinitionUri: ''
  }

  // 1. 検証セッションを発行させる。ポリシーサーバーを持たないノードでは
  //    例外になり、その場合はノード自身がクレデンシャルを検査する。
  let initializePs: { success?: boolean; message?: InitiateMessage } | null
  try {
    initializePs = await ProviderInstance.initializePSVerification(nodeUrl, {
      documentId: ddo.id,
      serviceId,
      consumerAddress,
      policyServer
    })
  } catch (error) {
    const messageText = error instanceof Error ? error.message : String(error)
    console.warn(`initializePSVerification unavailable; proceeding without a policy server: ${messageText}`)
    return undefined
  }

  const message = initializePs?.message as InitiateMessage
  const sessionId = extractSessionId(message)
  const openid4vc = extractOpenid4vc(message)

  if (!initializePs?.success || !sessionId) {
    console.warn('Policy server did not return a session id; proceeding without one.')
    return undefined
  }
  console.log(`Policy server session id: ${sessionId}`)

  // 2. アドレスのみ／SSI ポリシー無し：セッション ID だけがチケットになる。
  if (!requiresCredentialPresentation(ddo, serviceId)) {
    return { ...policyServer, sessionId }
  }

  // 3. SSIpolicy あり：walt.id によるクレデンシャル提示を実行する。
  const ssiApi = process.env.SSI_WALLET_API
  const walletId = process.env.SSI_WALLET_ID
  if (!ssiApi || !walletId || !openid4vc) {
    console.warn('SSI presentation required but SSI wallet is not configured; the node will deny the download.')
    return { ...policyServer, sessionId }
  }

  try {
    const presentationDefinition = await getPresentationDefinition(sessionId, nodeUrl)
    const session = await connectToSSIWallet(signer, ssiApi)
    const credentials = await matchCredentialsForPresentationDefinition(
      ssiApi, walletId, presentationDefinition, session.token
    )
    if (credentials.length === 0) {
      throw new Error('No wallet credential satisfies the asset presentation definition')
    }

    const dids = await getWalletDids(walletId, session.token, ssiApi)
    if (dids.length === 0) throw new Error('No DIDs found in the SSI wallet')
    const preferredDid = process.env.SSI_WALLET_DID
    if (preferredDid && !dids.some((d) => d.did === preferredDid)) {
      throw new Error(`SSI_WALLET_DID ${preferredDid} not found in the wallet`)
    }
    const did = preferredDid ?? dids[0].did

    const resolvedRequest = await resolvePresentationRequest(walletId, openid4vc, session.token, ssiApi)
    const result = await sendPresentationRequest(
      walletId, did, resolvedRequest, credentials.map((c) => c.id), session.token, ssiApi
    )
    if (result.errorMessage || result.redirectUri?.includes('error')) {
      throw new Error('Credential presentation was rejected by the verifier')
    }
  } catch (error) {
    const messageText = error instanceof Error ? error.message : String(error)
    console.warn(`Policy-server SSI presentation failed (non-blocking): ${messageText}`)
  }

  // ノードはダウンロード時に検証セッションを再確認する。チケットを返しておく。
  return { ...policyServer, sessionId }
}
```

### `src/consume-dataset.ts`

全体をつなぐエントリーポイントです。解決 → 注文 → ダウンロードの順に処理します。

```ts
import 'dotenv/config'
import fs from 'node:fs'
import path from 'node:path'
import {
  Datatoken,
  ProviderInstance,
  downloadFile,
  orderAsset
} from '@oceanprotocol/lib'
import { DDOManager } from '@oceanprotocol/ddo-js'
import {
  createAquarius,
  createOceanConfig,
  createSigner,
  requireEnv
} from './config.js'
import { getPolicyServer, isV5Asset } from './policyServer.js'

// ノードが設定する Content-Disposition ヘッダーからダウンロードファイル名を読み取る。
function filenameFromResponse(response: Response): string | undefined {
  const disposition = response.headers.get('content-disposition')
  if (!disposition) return undefined
  const match = /filename\*?=(?:UTF-8'')?"?([^";]+)"?/i.exec(disposition)
  return match ? decodeURIComponent(match[1]) : undefined
}

async function main(): Promise<void> {
  // CLI 引数: <did> [outputDir] [serviceId]
  const did = process.argv[2]
  const outputDir = process.argv[3] ?? './downloads'
  const serviceIdArg = process.argv[4]
  if (!did) {
    console.error('Usage: npm run consume -- <did> [outputDir] [serviceId]')
    process.exit(1)
  }

  const nodeUrl = requireEnv('NODE_URL')
  const { signer, chainId } = await createSigner()
  const config = createOceanConfig(chainId, nodeUrl)
  const aquarius = createAquarius(nodeUrl)

  // 1. Ocean Node のメタデータキャッシュから DDO を解決する。
  const ddo = await aquarius.waitForIndexer(did)
  if (!ddo) throw new Error(`Asset ${did} was not found on the Ocean Node (${nodeUrl}).`)

  // 2. 本ガイドは DDO v5（Ocean Enterprise）のアセットのみを対象とする。
  if (!isV5Asset(ddo)) {
    throw new Error('This guide targets DDO v5 assets only; the resolved asset is not v5.')
  }

  // 3. 利用するサービスを選ぶ（既定では最初のもの）。
  const { services } = DDOManager.getDDOClass(ddo).getDDOFields() as {
    services: Array<{ id: string }>
  }
  const serviceId = serviceIdArg ?? services[0].id
  const serviceIndex = services.findIndex((s) => s.id === serviceId)
  if (serviceIndex < 0) throw new Error(`Service ${serviceId} does not exist on asset ${did}.`)

  // 4. ポリシーサーバー用オブジェクトを取得する。ノードがポリシーサーバーを
  //    動かしている場合、アクセス制御付きアセットでは sessionId が必須。
  const policyServer = await getPolicyServer(ddo, serviceId, signer, nodeUrl)

  // 5. 選択したサービスの datatoken を注文する（固定レート・無償の両方に対応）。
  const datatoken = new Datatoken(signer, chainId, config)
  const tx = await orderAsset(
    ddo, signer, config, datatoken, nodeUrl,
    undefined, undefined, undefined, undefined, undefined,
    serviceIndex
  )
  if (!tx) throw new Error('Order failed. Do you hold, or can you buy, the datatoken?')
  const orderTx = await tx.wait()
  if (!orderTx) throw new Error('Order transaction was not mined.')

  // 6. オンチェーンの注文を署名付きダウンロード URL と交換する。sessionId を
  //    リクエストに載せるため、policyServer は最後に渡す。
  const downloadResult = await ProviderInstance.getDownloadUrl(
    ddo.id, serviceId, 0, orderTx.hash, nodeUrl, signer, policyServer
  )

  // 7. getDownloadUrl は 1 回限りの署名付き URL（一般的）か、そのまま使える
  //    ペイロードを返す。1 度だけ取得・正規化してディスクへ書き出す。
  fs.mkdirSync(outputDir, { recursive: true })
  if (typeof downloadResult === 'string') {
    const response = await fetch(downloadResult)
    if (!response.ok) {
      const body = await response.text().catch(() => '')
      throw new Error(
        `Ocean Node rejected the download: ${response.status} ${response.statusText}\n${body}`
      )
    }
    const filename = filenameFromResponse(response) ?? 'file.out'
    const filePath = path.join(outputDir, filename)
    fs.writeFileSync(filePath, Buffer.from(await response.arrayBuffer()))
    console.log(`Downloaded: ${filePath}`)
    return
  }

  const { data, filename } = await downloadFile(downloadResult)
  const filePath = path.join(outputDir, filename ?? 'file.out')
  fs.writeFileSync(filePath, Buffer.from(data))
  console.log(`Downloaded: ${filePath}`)
}

main().catch((error) => {
  console.error(error)
  process.exit(1)
})
```

## トラブルシューティング

| 症状 | 考えられる原因 |
| --- | --- |
| `Asset ... was not found` | `NODE_URL` が誤っている、チェーンが違う、あるいは DID がまだインデックスされていない。 |
| `not v5` のエラー | DID が古い（v4／v1）アセットを指している。本ガイドは v5 専用です。 |
| `Order failed` | アカウントが datatoken の支払い／受け取りをできない（残高または価格設定の問題）。 |
| 注文後にダウンロードが拒否される（`sessionId` がない） | アセットがクレデンシャルで保護されている。ステップ 3 でポリシーサーバーの `sessionId` を取得し、`policyServer` オブジェクトを `getDownloadUrl` に渡してください（`SSIpolicy` が適用される場合は SSI ウォレットも設定します）。 |
| チェーン ID の不一致 | `RPC` が、DDO が公開されたチェーンとは別のチェーンを指している。 |

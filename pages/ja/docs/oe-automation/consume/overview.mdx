# ポータルを使わずにデータセットを利用する（Ocean Enterprise v2）

本章では、**ポータルを使わずに**、自分のアプリケーションやスクリプトから直接
**データサービスへプログラム的にアクセスしてダウンロードする** 方法を解説します。
対象は **[Ocean Enterprise](https://www.oceanenterprise.io/) を基盤とする Pontus-X の v2 スタック**であり、
アセットは **DDO v5** で記述され、`did:ope` の DID で識別されます。

利用処理を自社製品に組み込みたい場合、ダウンロードを自動化したい場合、あるいはライブラリを
アプリケーションに組み込む前に DID を手早く確認したい場合に役立ちます。

:::info
**`did:ope` と `did:op` の違い** — Ocean Enterprise（v2）のアセットは **`did:ope:`**
接頭辞を使います。従来の Pontus-X（v1）スタックでは `did:op:` でした。本章の内容はすべて
**`did:ope`** / DDO v5 のアセットを対象としています。v1 スタックを使っている場合は、
代わりに [アセットのダウンロード](/ja/docs/use-cases/download)（Nautilus）を参照してください。
:::

## 「利用する」とは

Ocean Enterprise におけるデータサービスのダウンロードは、次の短い一連の流れです。

1. Ocean Node からアセットのメタデータ（DDO）を **解決（resolve）** する。
2. 利用したいサービスの datatoken を **注文（order）** する（オンチェーンでの支払い／アクセス付与）。
3. その注文を、Ocean Node の provider コンポーネントが発行する短命の署名付き
   **ダウンロード URL** と **交換（exchange）** する。
4. 実データを **ダウンロード** する。

使用するアカウントは、すでに datatoken を保有しているか、購入できる（固定価格のアセットの場合）か、
受け取れる（無償／ディスペンサーのアセットの場合）必要があります。

## 2 つの統合方法

| 方法 | 向いている場面 | 手間 |
| --- | --- | --- |
| **[ocean.js](/ja/docs/oe-automation/consume/ocean-js)** | Node.js／TypeScript のアプリに利用処理を組み込みたい場合。細かく制御できます。 | コードを書く |
| **[Ocean CLI](/ja/docs/oe-automation/consume/ocean-cli)** | コードを書かずにファイルを取得したい場合。DID の動作確認にも。 | ノーコード |

どちらも **同じ手順** を実行し、同じ結果に至ります。とにかくファイルが欲しい場合は Ocean CLI から、
自分のアプリケーションに利用処理を組み込む場合は ocean.js を使ってください。

## 前提条件のチェックリスト

| 必要なもの | 必須か | 用途 |
| --- | --- | --- |
| アカウントの秘密鍵（`PRIVATE_KEY`） | **必須** | datatoken の支払い／受け取りを行う利用者アカウント。 |
| RPC エンドポイント（`RPC`） | **必須** | アセットが存在するチェーンの JSON-RPC。 |
| Ocean Node の URL（`NODE_URL`） | **必須** | メタデータキャッシュと provider（オフチェーンの参照）。 |
| 公開済みの v5 `did:ope` | **必須** | ダウンロード対象のアセット。 |
| ガス用のネイティブトークン | **必須** | 注文トランザクションを送信するため。 |
| 決済トークンの残高 | 有償の場合のみ | 固定価格のサービスにのみ必要。 |
| SSI ウォレット（`SSI_WALLET_*`） | 任意 | **クレデンシャルで保護された** アセットの場合のみ（後述）。 |

:::info
公開済みのアセットとその `did:ope` は Pontus-X カタログで探せます。
`NODE_URL` と `RPC` が、そのアセットが公開された **同じネットワーク** を指していることを確認してください。
[Pontus-X ネットワーク](/ja/docs/pontus-x-networks/quick-start) を参照してください。
:::

## クレデンシャルで保護された（SSI）アセット

DDO v5 のアセットは **クレデンシャルによる保護** を設定できます。データを引き渡す前に、Ocean Node が
ポリシーサーバーに問い合わせ、検証可能プレゼンテーションを（walt.id 経由で）検証します。この場合、
トランザクション用アカウントに加えて **SSI ウォレット** が必要です。
[v2 の 2 ウォレット構成](/ja/docs/getting-started/wallet-setup) を参照してください。

:::info
SSI に関する手順は **任意** であり、クレデンシャルで保護されたアセットにのみ必要です。保護されていない
アセットであれば、`SSI_WALLET_*` の変数は省略して構いません。最終的な判断は常に Ocean Node が行います。
クレデンシャルが実際に必要な場合は、ダウンロードが拒否され、その旨のエラーが返ります。
:::
